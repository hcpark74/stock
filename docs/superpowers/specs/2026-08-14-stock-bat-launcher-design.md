# stock.bat 수동 실행 런처 설계

작성일: 2026-08-14

## 1. 목적

`main.py`를 더블클릭 한 번으로 안전하게 띄우는 런처를 만든다. 대상 사용자는
PowerShell 명령어에 익숙하지 않은 운영자이며, 실행 실패 시 원인과 해결 방법을
화면에서 바로 읽을 수 있어야 한다.

기존 `scripts/restart_main.ps1`은 **이미 돌고 있는 프로세스를 안전하게 교체**하는
도구다. 이 런처는 **아무것도 안 돌고 있을 때 처음 띄우는** 도구이며, 역할이
겹치지 않는다.

### 범위 밖

- 작업 스케줄러 자동 기동, 부팅 시 자동 시작, 워치독 연동
- 실행 중인 프로세스의 종료·재시작 (`restart_main.ps1`이 담당)
- 가상환경 생성과 패키지 설치 (안내만 하고 수행하지 않음)

## 2. 제약: 전략 지문을 바꾸지 말 것

`src/release.py`의 `strategy_fingerprint()`는 두 가지를 해시한다.

1. `_STRATEGY_FILES` 19개 파일의 바이트 — **`main.py`가 여기 포함된다**
2. `_STRATEGY_ENV_PREFIXES`에 걸리는 프로세스 환경변수
   (`F1_`, `F2_`, `F3_`, `F4_`, `F5_`, `PAPER_FAST_`, `TRAILING_SHADOW_`,
   `VI_`, `BALANCE_SNAPSHOT_`, `EXIT_RECONCILE_`, `KIS_RATE_`,
   `KIS_MAX_TRANSIENT_`, `KIS_TRANSIENT_`, `KIS_LOW_PRIORITY_`)
   와 `FORCE_CATCHUP`

지문이 바뀌면 PAPER 정상 청산 실적이 0회부터 다시 시작한다
(`docs/REAL_TRADING_CHECKLIST.md`). 실적 축적에는 2~3개월이 걸린다.

따라서 이 작업은 다음을 지킨다.

- **`main.py`를 포함한 `_STRATEGY_FILES` 19개 파일을 수정하지 않는다.** 런처
  본체는 신규 파일로만 만든다. 이 작업이 수정하는 기존 파일은
  `tests/test_release.py`와 `README.md`뿐이며, 둘 다 목록 밖이라 지문에 영향이
  없다.
- **런처는 전략 환경변수를 주입하지 않는다.** 설정하는 변수는 `PYTHONUTF8`과
  `PYTHONUNBUFFERED` 둘뿐이며, 둘 다 위 접두사 목록 밖이다.

## 3. 파일 구성

| 파일 | 역할 |
|---|---|
| `stock.bat` (저장소 루트) | 얇은 shim. 경로 확인 후 PowerShell 스크립트 호출, 종료 시 `pause` |
| `scripts/start_main.ps1` | 사전 점검과 포그라운드 실행 로직 전부 |
| `tests/test_release.py` (추가) | 런처 환경변수가 지문을 바꾸지 않음을 단언 |

`stock.bat`은 기존 `acl.bat`의 패턴을 따른다: `%~dp0`로 저장소 경로를 잡고,
대상 스크립트 존재를 먼저 확인한 뒤
`powershell -NoProfile -ExecutionPolicy Bypass -File`로 호출한다.

`acl.bat`과 달리 관리자 권한은 요구하지 않는다.

## 4. 사전 점검

순서대로 수행하고, 실패하면 그 지점에서 멈춘다. 모든 실패 메시지는 **원인과
해결 명령어를 함께** 출력한다.

| # | 점검 | 통과하지 못했을 때 |
|---|---|---|
| 1 | `.venv\Scripts\python.exe` 존재 | `python -m venv .venv`와 `pip install -r requirements.txt` 안내 후 종료 (exit 1) |
| 2 | `main.py` 존재 | 저장소 위치가 잘못됐음을 안내 후 종료 (exit 1) |
| 3 | `.env` 존재 | `copy .env.example .env` 안내 후 종료 (exit 1) |
| 4 | `KIS_MODE` 유효성 | REAL이면 확인 입력 요구, 알 수 없는 값이면 종료 (아래 4-1) |
| 5 | 중복 실행 여부 | 이미 실행 중이면 안내 후 **정상 종료 (exit 0)** (아래 4-2) |
| 6 | UI 포트 가용 | 포트 점유 시 `.env`의 `UI_PORT` 변경 안내 후 종료 (exit 1) |
| 7 | 장 시간 | 차단하지 않고 안내만 (아래 4-3) |

### 4-1. 모드 확인

`.env`를 파싱해 `KIS_MODE`를 읽고 화면에 표시한다.

- `DRY_RUN`, `PAPER`: 표시만 하고 통과
- `REAL`: 계좌번호를 마스킹해 함께 보여주고 `y` 입력을 받는다. 다른 입력이면
  종료(exit 0, 사용자 취소이므로 오류 아님)

계좌번호는 `.env.example`이 명시한 우선순위를 따른다: `KIS_ACCT_NO`가 있으면
그것을, 없으면 `KIS_ACCOUNT_NO`를 쓴다. 표시할 때 앞자리를 가리고 뒤 4자리만
보여준다.

`KIS_MODE`가 비어 있거나 위 세 값이 아니면 오류로 처리하고 종료한다(exit 1).
알 수 없는 모드를 기본값으로 추측하지 않는다.

### 4-2. 중복 실행 확인

`main.py`는 `main.pid`에 파일 잠금 기반 단일 인스턴스 가드를 이미 갖고 있다.
런처의 역할은 **차단이 아니라 안내**다. 잠금 실패로 새 프로세스가 조용히 죽는
대신, 실행 전에 상황을 설명한다.

판정 절차:

1. `main.pid`를 읽는다. 없으면 미실행으로 본다.
2. 해당 PID가 살아 있는지 `tasklist`로 확인한다.
3. 살아 있으면 그 프로세스의 실행 파일 경로가 이 저장소의
   `.venv\Scripts\python.exe`인지 대조한다. 다르면 PID 재사용이므로 미실행으로
   본다.

실행 중으로 판정되면 PID, UI 주소(`http://127.0.0.1:<UI_PORT>`)를 보여주고
다음을 안내한 뒤 종료한다.

> 이미 실행 중입니다. 재시작하려면 `scripts\restart_main.ps1`을 사용하세요.

런처는 프로세스를 종료하지 않는다. 종료·재기동은 `restart_guard.py` 안전점검을
거치는 `restart_main.ps1`의 책임이며, 안전critical 로직을 두 벌로 두지 않는다.

### 4-3. 장 시간 안내

차단하지 않는다. 초보자가 "실행했는데 아무 일도 없다"로 헤매는 것을 막는
설명이 목적이다.

기준 시각은 `src/schedule_times.py`에서 읽지 않고 런처에 상수로 두되, 근거를
주석에 남긴다. 이 값들은 자주 바뀌지 않으며, 런처가 전략 모듈을 import하면
실행 경로가 무거워진다.

| 현재 시각 (KST) | 안내 |
|---|---|
| 08:59:45 이전 | 정상 — 모든 단계가 예정대로 동작합니다 |
| 08:59:45 ~ 09:11 | 진입 시도 구간입니다. 늦게 켰다면 일부 단계를 건너뜁니다 |
| 09:11 ~ 15:15 | 신규 진입은 없습니다. 보유 감시와 마감 청산만 동작합니다 |
| 15:15 이후 | 오늘 매매 시간은 끝났습니다 |
| 주말 | 장이 열리지 않습니다 |

공휴일 판정은 하지 않는다. 런처가 휴장일 달력을 갖는 것은 범위를 넘고, 앱이
이미 KIS 응답으로 휴장을 처리한다.

## 5. 실행

```powershell
$env:PYTHONUTF8 = "1"
$env:PYTHONUNBUFFERED = "1"
& $venvPython -u main.py 2>&1 | Tee-Object -FilePath $consoleLog
```

- 작업 디렉터리는 저장소 루트로 고정한다.
- 가상환경을 `Activate.ps1`로 활성화하지 않고 `.venv\Scripts\python.exe`를 직접
  호출한다. 활성화는 실행 정책과 프로필 간섭을 타지만 직접 호출은 그렇지 않으며,
  `restart_main.ps1`도 같은 방식이다.
- `-u`와 `PYTHONUNBUFFERED`로 출력 버퍼링을 없앤다. 이것이 없으면 `Tee-Object`가
  블록 단위로 몰아 출력해 실시간 로그처럼 보이지 않는다.
- `2>&1`로 stderr를 합쳐 트레이스백도 파일에 남긴다.

## 6. 로그

`data\logs\launcher_YYYYMMDD_HHmmss.log`에 기록한다. 실행마다 새 파일이다.

기존 `data\logs\YYYYMMDD.jsonl`과 **별개 파일이며 대체하지 않는다.** jsonl은
`src/utils/logger.py`의 `_JsonLinesHandler`가 쓰는 구조화 로그로, `log()` 호출만
담긴다. 다음은 jsonl에 남지 않는다.

- Python 크래시 트레이스백
- uvicorn 자체 로그
- `logger.setup()` 이전 단계의 기동 실패 메시지

런처 로그의 존재 이유가 이 세 가지다.

### 로그 정리

런처 로그는 실행마다 쌓이므로 무한히 늘어난다. 실행 시작 시 `launcher_*.log`
중 **최근 30개만 남기고 오래된 것부터 삭제**한다. 파일명의 타임스탬프가 아니라
파일 수정 시각을 기준으로 정렬한다.

## 7. 종료 처리

| 상황 | 동작 |
|---|---|
| 정상 종료 (exit 0) | 종료 코드와 로그 경로 표시 |
| Ctrl+C | 사용자 중단임을 표시하고 로그 경로 안내 |
| 비정상 종료 (exit != 0) | 로그 마지막 15줄을 화면에 다시 출력하고 경로 안내 |

`stock.bat`은 마지막에 `pause`로 창을 유지한다. 창이 즉시 닫혀 원인을 못 보는
상황을 막는 것이 목적이며, 사전 점검 실패로 조기 종료할 때도 동일하다.

### 알려진 한계

Ctrl+C로 급히 중단하면 `Tee-Object` 버퍼의 마지막 몇 줄이 파일에 기록되지 않을
수 있다. jsonl은 이벤트마다 파일을 열고 닫으므로 영향받지 않는다. 사후 분석은
jsonl을 우선 본다.

## 8. 검증

### 자동 테스트

`tests/test_release.py`에 다음을 추가한다.

- 런처가 설정하는 `PYTHONUTF8=1`, `PYTHONUNBUFFERED=1`을 환경에 넣어도
  `strategy_fingerprint()`가 변하지 않는다.

이 테스트는 나중에 누군가 런처에 전략 환경변수를 추가했을 때 실패한다. 지문
리셋은 조용히 일어나고 두 달치 실적을 되돌리므로, 회귀를 코드로 고정한다.

### 수동 검증

`.ps1`과 `.bat`은 이 저장소의 pytest 대상이 아니므로 수동으로 확인한다.

1. `KIS_MODE=DRY_RUN`으로 정상 기동 — 로그가 창에 실시간으로 흐르고
   `launcher_*.log`에도 같은 내용이 남는지
2. 점검 1 실패: `.venv`를 임시로 이름 변경
3. 점검 3 실패: `.env`를 임시로 이름 변경
4. 점검 4: `KIS_MODE=REAL`로 두고 확인 프롬프트가 뜨는지, `n` 입력 시 실행되지
   않는지
5. 점검 5: `main.py`를 먼저 띄운 상태에서 `stock.bat` 실행 — 안내 후 종료되고
   기존 프로세스가 살아 있는지
6. 점검 6: 다른 프로세스로 `UI_PORT`를 점유한 상태에서 실행
7. 종료 처리: 실행 중 Ctrl+C, 그리고 즉시 크래시하는 상황에서 마지막 15줄이
   다시 출력되는지
8. 로그 정리: `launcher_*.log`를 31개 이상 만든 뒤 실행해 30개로 줄어드는지

### 지문 불변 확인

구현 완료 후 `strategy_fingerprint()` 값이 작업 전과 같은지 직접 비교한다.
신규 파일만 추가했으므로 같아야 한다.
