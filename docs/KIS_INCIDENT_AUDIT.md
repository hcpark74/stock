# KIS 조회 전용 사고 분석 런북

> **검증일**: 2026-07-21
> **적용 이벤트**: `STALE_POSITION_DETECTED`, `BALANCE_QUERY_FAILED`, 미체결 주문 불일치
> **원칙**: 조회 결과는 보조 증거이며 주문·정정·취소나 상태 자동 복구에 사용하지 않는다.

## 1. 안전 조건

- 기본 계정은 `KIS_MODE=PAPER`만 허용한다.
- 09:00~09:11에는 실행하지 않는다.
- 계좌 조회 감사는 15:40 KST 이후에만 실행한다.
- 조회는 잔고와 당일 미체결 주문 GET 두 건으로 제한한다.
- 계좌번호, 토큰, 앱 시크릿, 종목별 원문, 주문번호, 금액은 화면이나 조사 기록에 남기지 않는다.
- Trading MCP는 주문 도구를 분리할 수 없어 사용하지 않는다. Code Assistant는 계좌 API를 호출하지
  못하므로 실제 원장 대조는 기존 `kis_rest`의 읽기 전용 경로로 수행한다.

실행 명령:

```powershell
python scripts\kis_phase4_readonly_audit.py
```

감사 도구는 다음 조건에서 호출 전에 중단한다.

- PAPER가 아닌 계정
- 09:00~09:11 또는 15:40 이전
- 계좌 설정 누락
- 인증 실패

## 2. `STALE_POSITION_DETECTED` 확인 순서

1. 자동 진입이 차단됐는지 확인하고 `today_state.json`이나 격리 사본을 수정·삭제하지 않는다.
2. `data/state`, 당일 JSONL, SQLite DB를 읽기 전용으로 보존한다. 원본을 외부에 공유하지 않는다.
3. 안전 시간과 PAPER 계정을 확인한 뒤 감사 도구를 실행한다.
4. KIS 잔고조회 성공 여부와 보유 종목 **건수**를 확인한다.
5. 잔고조회가 성공한 경우에만 당일 미체결 주문을 조회한다.
6. KIS 미체결 주문번호를 DB `orders.kis_order_id`와 당일 JSONL의 주문 식별자에 대조한다.
7. 아래 판정표에 따라 처리한다. 도구가 상태 파일이나 DB를 자동 수정하게 하지 않는다.

| KIS 원장 | DB·JSONL | 판정 | 후속 조치 |
|---|---|---|---|
| 보유 0, 미체결 0 | pending 0 | 원장상 안전 | 격리 상태와 로그 원인을 검토한 뒤 운영자가 재시작 여부 결정 |
| 보유 있음 | 상태에 보유 없음 | 포지션 불일치 | 자동매매 중지 유지, MTS/HTS에서 수동 확인·정리 |
| 미체결 있음 | DB/JSONL에 없음 | 주문 감사 누락 | 추가 주문 금지, MTS/HTS에서 주문 상태 확인 |
| 미체결 없음 | DB pending 있음 | 로컬 상태 지연 | KIS 체결/취소 내역 확인 후 DB 보정은 별도 승인 절차로 수행 |
| 조회 실패 또는 응답 불완전 | 무관 | 판정 불가 | 보유 0으로 간주하지 않고 즉시 중단 |

## 3. 즉시 중단 기준

다음 중 하나라도 발생하면 추가 KIS 호출을 하지 않는다.

- HTTP 429
- `msg_cd=EGW00201` 또는 의미가 확인되지 않은 호출 제한 코드
- `rt_cd != 0`
- 인증·계좌 권한 오류
- `output1`/`output2`의 타입 오류 또는 필수 잔고 요약 필드 누락
- 응답 파싱 예외, 네트워크 실패 또는 예상하지 못한 예외

`stop_on_rate_limit=True` 조사 모드는 HTTP 429와 `EGW00201`을 자동 재시도하지 않는다. 잔고 단계가
실패하면 미체결 단계로 진행하지 않는다. 성공 응답의 빈 목록은 “없음”이고, 컨테이너 또는 필드 누락은
“조회 실패”로 구분한다.

## 4. 조사 기록 양식

계좌번호·토큰·앱 키·주문번호·종목·금액은 기록하지 않는다.

```text
[KIS 읽기 전용 사고 조사]
조사 시각(KST):
조사자:
조사 목적:
트리거 이벤트: STALE_POSITION_DETECTED | BALANCE_QUERY_FAILED | 기타
계정 구분: PAPER | REAL(별도 승인 번호 필수)
봇 상태: 실행 중 | 중지
자격 증명 분리: 봇과 별도 PAPER | 봇 중지 후 공용 | 해당 없음(Code Assistant)
사용 도구/버전:
사용 경로: balance GET, unfilled-orders GET
조회 대상/TR·데이터 기간:
호출 횟수:

KIS 잔고: SUCCESS | FAILED | NOT_RUN
보유 종목 수:
필수 필드 확인: PASS | FAIL
KIS 미체결 수:

DB 당일 주문 수:
DB pending 수:
JSONL 이벤트 수:
KIS 미체결 중 DB 누락 수:
KIS 미체결 중 JSONL 누락 수:
DB pending 중 KIS 원장 부재 수:

판정: MATCH | REVIEW_REQUIRED | STOPPED
중단 사유/메시지 코드:
증거 파일: DB 경로, JSONL 날짜, stale state 사본 경로
후속 조치:
승인/확인자:
```

Code Assistant처럼 KIS 계정 API를 호출하지 않는 도구도 조사 시각, 목적, 도구/버전, 계정 구분
`해당 없음`, 조회한 API 명세·공식 소스를 기록한다. 앱 키, 시크릿, 토큰, 계좌번호와 응답 원문은
어떤 경로에서도 기록하지 않는다.
