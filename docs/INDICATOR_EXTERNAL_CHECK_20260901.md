# 봉·지표 외부 대조 (2026-09-01)

> 관련: [멀티 트랙 전략 병행 운용 설계](superpowers/specs/2026-08-25-multi-track-strategy-design.md) §7,
> [트랙 B 그림자 가동 설계](superpowers/specs/2026-08-27-track-b-shadow-design.md) §7·§17.1

지금까지 봉과 지표의 검증은 전부 **내부 기준**이었다 — 손계산 대조는 "우리 공식이 우리
의도대로 구현됐다"를 보일 뿐, 증권사와 같은 값이 나오는지는 말하지 않는다. 규칙 연구가
이 위에 서 있으므로 외부 기준을 한 번 세운다.

## 1. 기준

| 항목 | 값 |
|---|---|
| 대조 화면 | 알파스퀘어 1분봉 차트 (증거: `docs/screenshot/`) |
| 보조 확인 | Google Finance (`443670:KOSDAQ`) |
| 종목·날짜 | **443670 에스피소프트 / 2026-08-31** |
| 우리 쪽 데이터 | `data/backtest_bars/20260831_443670.json` (KIS 일별분봉 `FHKST03010230`) |
| 우리 쪽 지표 | [`src/indicators.py`](../src/indicators.py) — SMA / EMA / MACD(12,26,9) |

## 2. 결과 — 전부 일치

값뿐 아니라 **최고·최저가 찍힌 분까지 같다.** 체결의 시각 귀속(분 경계)이 증권사와 동일하다는
뜻이다. 거래량도 봉 단위로 일치한다.

별도로 **우리 실시간 틱 집계 봉과 공식 분봉 API를 380분 비교해 379분이 OHLCV 전 필드
일치**했다. 어긋난 15:19 한 분은 그날 캡처 창이 15:15여서 정정을 받지 못한 분이다
(`26a9558`로 창을 15:20으로 옮겼다).

### 2.2 MACD — 공식이 검증됐다

| | MACD | 시그널 | 히스토그램 |
|---|---:|---:|---:|
| 알파스퀘어 12:48 | 26.80 | 14.39 | 12.41 |
| 우리 12:48 | **26.80** | **14.39** | **12.41** |

**12:48은 09:00부터 228번째 봉이다.** EMA26의 평활계수는 `2/27 ≈ 0.074`이므로 초기값의
잔존 영향은 `(1-0.074)^228 ≈ 10^-8` 수준으로 소멸한다. 따라서 이 일치는 초기화가 같아서가
아니라 **계산식이 같기 때문**이다 — 평활계수, 시그널선을 "MACD가 정의된 구간만 모아 EMA를
걸고 원래 자리로 되돌리는" 방식까지 증권사와 동일하다.

## 3. 값이 다른 구간 — 설계상 의도된 차이

09:17에서는 비교가 **불가능**하다.

| | 09:17 |
|---|---|
| 알파스퀘어 | MACD 49.42 / 47.32 / 2.10 |
| 우리 | **전부 `None`** (정의 안 됨) |

09:17은 09:00부터 18번째 봉이다. 우리 지표의 최초 정의 시각은 다음과 같다.

| 지표 | 최초 정의 |
|---|---|
| SMA20 | 09:19 (20번째 봉) |
| MACD선 | 09:25 (26번째 봉) |
| 히스토그램 | **09:33** (34번째 봉) |

차이의 원인은 캡처에 직접 찍혀 있다 — 차트 왼쪽 주석이 `최저 3,780 − 08.28. 15:30`이다.
**알파스퀘어는 전일 데이터를 이어서 지표를 계산하고, 우리는 매일 09:00부터 새로 자란다.**

이것은 결함이 아니라 모스펙 §7.1의 확정 결정이다 — 전일 분봉을 시드로 쓰면 갭이 큰 종목에서
MACD가 개장 즉시 극단값이 되어 무의미한 신호를 쏟아내고, 하필 이 전략이 고르는 것이 갭이
가장 큰 종목이다. 트랙 B의 진입 창이 09:35인 이유가 이 제약이다.

**따라서 아침 구간에서 우리 지표와 증권사 차트가 다른 것은 정상이다.** 09:35 이전 값을
증권사 화면과 맞춰보고 "우리가 틀렸다"고 판단하면 안 된다.

> **✅ 해소됨 (2026-09-01).** 위 본문은 이 차이를 관측한 그날의 판단이고, 그대로 남긴다.
> 그 뒤 전 거래일 봉을 지표 입력 앞에 붙이는 워밍업을 넣어 **같은 종목·같은 시각이
> 알파스퀘어와 소수점까지 일치**하는 것을 실측했다 — 20260831 443670 09:17 MACD
> `49.42 / 47.32 / 2.10`. 위 표의 "최초 정의" 시각은 워밍업이 없을 때의 이야기이고,
> 워밍업이 붙은 행은 당일 첫 봉부터 값이 선다.
>
> 다만 **본문의 경고는 여전히 유효하다.** 워밍업이 붙지 않은 행(전 거래일 봉이 없거나
> 세션이 잘린 경우)은 `warmed=false`로 표시되며, 그런 행을 증권사 화면과 맞춰보고
> 틀렸다고 판정하면 안 된다. 진입 창 09:35은 이번 작업에서 건드리지 않았다.
>
> 실측: `docs/INDICATOR_WARMUP_VERIFY_20260901.md`

## 4. 이 대조가 말하지 않는 것

- **RSI·볼린저·ATR 등은 검증 대상이 아니다** — 애초에 구현돼 있지 않다. 지금 있는 것은
  SMA·EMA·MACD 셋뿐이다.
- **우리가 그린 차트를 사람이 본 적은 여전히 없다** — 그림자 스펙 §17.1은 미해결이다.
  이번에 본 것은 증권사 차트이지 우리 차트가 아니다.
- **다른 종목·다른 날에서도 맞는다는 것** — 하루 한 종목을 봤다. 다만 캔들이 공식 분봉 API
  원본이고 지표가 순수 함수이므로, 이 결과가 종목에 따라 달라질 이유는 없다.

## 5. 부수 발견 — 공식 API는 15:30 마감 단일가를 준다

```
15:30  시가 3,740  고가 3,740  저가 3,740  종가 3,740  거래량 80,634
```

Google Finance의 전일 종가 3,740과 일치한다. 즉 **15:30 단일가가 그날의 진짜 종가**이고,
15:19 종가 3,680보다 1.6% 높다.

이는 `26a9558`에서 `CAPTURE_UNTIL`을 15:20으로 정한 판단을 다시 볼 근거다. 그때는
"15:20~15:30 구간에 무엇이 오는지 실측한 바 없다"가 이유였는데, **백테스트가 쓰는 봉에는
15:30이 이미 들어 있다.** 규칙 연구가 보는 데이터와 실시간 캡처가 보는 데이터가 마지막
봉에서 갈린다. 별건으로 다룬다.
